# Private access security model

Cloudflare Access supplies a signed identity assertion. The Pages server verifies RS256 signature with the team's HTTPS JWKS, exact issuer/audience, expiry, issued-at, subject and email. Unsigned email headers, browser roles, query-string tokens and Supabase browser sessions cannot authorize the private deployment. Exact hostname checks also deny unexpected Pages aliases and previews. Every protected request then calls PostgreSQL enrollment authorization without caching its result. Database, JWT-key or configuration failures deny access.

Only the confirmed, previously authorized Supabase administrator is bootstrapped into admin enrollment; visiting first, knowing an email or controlling the hosting account creates no classroom role. Email is bound to the verified Access subject on first successful access. Rebinding an identity requires an audited owner-side database correction, not a student endpoint.

Enrollment tables and audit logs have RLS enabled, no browser policies and no anon/authenticated grants. Privileged RPCs are executable only by service_role. Administrative SQL commands independently verify the server-supplied administrator ID, reject changing administrator records, use server timestamps, lock rows and require the current revision. Students cannot supply their own actor, role, approval, dates or timestamp. History records each mutation; denied requests are logged at a bounded rate. The dashboard reads the latest 200 events. Audit logs contain enrollment PII and must remain administrator-only; do not copy them into public issues.

The private browser calls only same-origin endpoints. Mutations require the exact Origin and a random double-submit token tied to a Secure, HttpOnly, SameSite=Strict, __Host- cookie. Cross-site embedded requests, fetches and writes are rejected. A cross-site top-level GET document navigation is permitted through the metadata filter because Cloudflare OTP returns from a different origin; it still must pass the same cryptographic JWT, live enrollment and resource checks. Per-member rate limits run in PostgreSQL (1200 protected requests/minute, covering initial assets); the legacy API retains its existing limits. JSON has a 32 KB limit; file uploads have reservation and hard size caps. Unexpected errors are returned generically, without tokens or credentials in logs. Server time determines enrollment access; client clocks only affect display.

Cloudflare's `__cf_access_message=logged_out` is display context, never authentication or revocation evidence. When a later successful login retains that marker, the server removes it with a single same-origin redirect only after full authorization. Missing/invalid assertions still deny access. The unauthenticated fallback offers a clean Sign in link rather than another logout, with no automatic logout/relogin chain. Structured denial diagnostics include only bounded error reasons, route categories and request-metadata booleans, never identity claims, cookie/JWT values or query strings.

All responses—including static assets and file downloads—use private/no-store browser and CDN headers, nosniff, no-referrer, frame denial, HSTS and a CSP. The teaching platform's existing isolated code runners require inline/blob scripts and eval capabilities, so the CSP allows those capabilities; it is not claimed to be a strict CSP or a replacement for the existing opaque-origin iframe/worker sandbox. No authentication or enrollment secret is available to those sandboxes. The built PDF viewer excludes PDF scripting and renders canvases without PDF link/form actions.

On the private site only an admin can reserve, upload, finalize, edit, organize or trash resources. Server-side validations and the existing resource_command checks remain in place. No Storage URL or service key reaches the student. Published-only checks apply on every download; active administrators can read drafts. Enrollment is checked at request start; an already authorized, in-flight stream is not retroactively erased. Existing uploads and versions are preserved.

Open tabs poll every 15 seconds, also checking on focus/pageshow/visibility changes and at expiry. A failure unmounts the entire app, including previews and runners. Browser timer throttling/network delays mean the UI lock is approximate; the server denies the next request immediately after revocation is committed. Already delivered lesson code, browser memory, screenshots, offline copies and downloads cannot be recalled. Never describe frontend polling as the security boundary.

GitHub Pages and the public repository are separate exposure paths until the owner approves the documented cutover. The additive migration initially keeps the legacy library operating. Setting the private_resources_enforced cutover switch closes that gateway; enabling the Cloudflare deployment alone does not do this. No public site or data is silently removed.

Report a suspected issue privately to the repository owner; do not include credentials, live JWTs or student details in public issues. Rotate a compromised server secret in Supabase and Cloudflare, then redeploy, without adding it to frontend variables.
